# V13.5 三段行为修复提案（未实施、未启动训练）

本提案根据 `v13_ascent_version_history_20260914.md`、`v135_cross_version_root_cause_review_20260919.md`、`v135_17100_failure_attribution_20260920.md` 和当前代码提出。先前锁定进度、全身结算修补仅通过接线验收，尚无行为改善证据。

## 历史约束

- V13 证明左右分相外观可达；冻结严格评估没有证明逐级长链稳定可达。不能据此排除 phase 可观测性问题。
- V13.1 的 escrow/严格结算曾使实际保留的正向信用很少。
- V13.2 的内部 style 指标与物理完成脱离；独立 style critic 不是已证明的解决方案。
- V13.3/V13.4 已试过相邻/三阶链奖励，真实链访问仍非常稀少。再命名 cycle/chain 不是新方法。
- V13.5 后轮完成收益增加而全身支撑恶化。当前最后一次修补尚未训练，因此不能说它已经改变了行为。

## 建议实施包

1. 保留现有任务、native 63D MLP Actor、574D Critic、8192×24 及当前 PPO。既有强 locomotion 驱动作为基线。先不增加全局 entropy。
2. 上楼同时处理样本与信用：按物理 B1 支撑、B1→B2、B2→B3 的访问瓶颈安排起始状态采样；只使用物理可行、经仿真稳定检验且与 live ledger 一致的状态。新动作、log probability、GAE 全部由当前策略重新采集，不重放旧动作或旧 advantage。保留完整起点环境及独立正式分布评估；采样课程不能替代完整链验收。已有近楼梯退火只增加 approach 样本，不足以保证 B2 阶段样本。
3. 将现有 ascent multiplier 改为当前物理阶的有界有效前进信用。奖励必须依赖当前阶安全单腿推进及相邻异侧支撑，不能仅凭历史 chain>0 无限持有。按每阶首次前进距离限制辅助信用；停住、后退重走、跳过该阶不能重复领取。保留小额即时 progress，不能重回全部延迟结算。multiplier 当前仍以 scanner `target_match` 为门槛，应改为锁定目标生命周期。
4. 用相同地形、指令、起点、终点和时间上限计算完整 reward 账本，包括失败、停滞、到达后的奖励；匹配 return、raw advantage、sample count 和 surrogate sum。只有这类结果能支持“有效交替更赚钱”，不能用单项 bonus 的名义权重证明。
5. 下楼将原有局部 shaping 合并为全身支撑转移质量，监测从进入下降边缘前开始，进度支付仍需真实下降。质量包括承重接触及其时间演化、机身/四轮相对前进、机身 clearance 与局部支撑地形、俯仰及俯仰角速度、接触轮的滚动一致性、双侧有宽容区的腿部工作空间。腿长一个数不能区分后伸/前折；不固定关节目标、前后载荷比例或每帧四轮接触。支撑多边形/载荷均为诊断代理，不能单独作为动态稳定性保证。
6. 下楼过程质量必须影响有效前进信用，不能只在最终碰地给奖励。末端同时要求真实后支撑、前部持续可用支撑以及工作空间恢复；中途允许正常摆动与负载迁移。上一补丁的“四轮同时接触+绝对pitch阈值”只适合有限的结算检查，应避免变成整个下降过程的静态姿态目标。
7. 楼梯出口与恢复成功分离：以末级物理边缘、前后轮通过情况和平台地形证据开始 recovery/blending，不以已恢复直立或速度跟踪成功为入口。目前 `flat_blend` 在 `settled` 后才增长，而且只乘 anti-crawl，既启动太晚，也没有真正淡出 stair auxiliary。改为几何出口之后逐渐淡出 stair auxiliary、淡入 flat recovery；成功事件只负责一次结算。遮挡导致无riser不能单独当出口；旧中间台阶 completion 不得授权后续误判。

## 验证与边界

先用固定正反例轨迹检查：跳级、重复接触、抬腿不落地、卸载前轮、后腿后伸/折叠、停在出口、扫描器短暂丢边缘。对全部实际 reward 做逐项支付审计。然后分阶段短训练，同一套正式分布评估三个目标，避免一次大改后无法归因。

上楼必须报告物理 B1/B2/B3 到达率、按楼梯总级数归一的完整交替链率、skip/dual，以及速度；下楼报告拖伸/折叠持续时间、接触滚动滑移、载荷迁移、机身俯仰变化及通过率；平地报告从真实末级通过到正常 locomotion 的延迟。退出判断必须独立于奖励成功事件。

短训练应先看到阶段访问和物理行为改善；只有奖励升高、链不增长或姿态恶化就停止候选。不得以编译、冒烟或一次 PPO update 作为长训行为 GO。若匹配条件下 ALT advantage 有优势却被更新压制，再讨论 PPO 更新保留约束；尚无证据时不直接引入梯度手术。
