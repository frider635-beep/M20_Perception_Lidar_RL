# V11.1 有驻留时间的上楼支撑交接与平地姿态（2026-09-24）

## 现象与代码证据
用户观察两前腿近同步上阶、领先腿未持续支撑即抢上下一阶，以及平地/楼梯出口轻微倾斜低姿态。旧 same_tread_handoff 只需两腿各有3帧支撑、曾出现单侧先确认，无领先腿驻留/跟随起步/共同支撑保持契约。20ms 控制下，20ms 落地差也能领取旧完成奖励。

## 修法
仅 V11.1 timed_support_cycle 开关接入新模块 v111_support_cycle.py；V11/V13.5 默认路径不进入新状态机。领先侧自由；其先在当前踏面建立稳定支撑、对侧仍在下级支撑，确认驻留后允许有奖励的跟随；领先腿在跟随期间保持支撑，双前轮共同驻留后结算。时间、力与滑移阈值统一在 M20V111RearPostureCfg。世界坐标缓存目标避免扫描换槽打断驻留。同步/过早跟随/失去支撑不给完整交接奖励，但物理完成仍允许重新同步。

分阶段进度使用历史最佳增量、同一踏面预算持久化、事件除以step_dt；速度和前进正收益在待交接阶段降低，有限的真实驻留窗口免速度不足成本。纯平地与出口姿态使用四轮邻近射线和前向平面覆盖、方向性边缘排除；惩罚低离地高度、倾斜和横滚俯仰速度，不以轮子高度当作地面高度，不要求先完成楼梯才能触发。

Actor63/Critic568/Action16、MLP/PPO维持。奖励侧状态不裁剪actor动作。旧模型不会因改奖励立即学会节奏。
