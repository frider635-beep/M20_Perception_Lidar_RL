# model_54300 平地四肢伸展诊断

对象为用户明确指定的 V11.2 run `2026-09-27_11-31-00_v112_handoff_tread20_44_resume43300_e8192_r24/model_54300.pt`，及 deploy_63d 的 high-descent / speed 1.0 / ROS domain 58 回放。原日志目录 `/tmp/m20_perception_deploy_63d_sim2sim/run/20260927_200305_2930716`。

本轮只增加诊断脚本和证据，不修改训练奖励、不重启训练、不改部署源代码。训练源与启动时 manifest 对照无漂移。当前主任务是定位，修复效果没有宣称通过。

## 确认一：训练和实际部署二进制使用不同关节零点

- 保存的 env.yaml、机器人资产、实例化环境中的 default_joint_pos 三者一致：前腿 hipy/knee 为 -0.3/0.6，后腿为 0.3/-0.6 rad。
- 用户实际 staged C++ policy_smoke_test 的 M20_POLICY_DEBUG 输出证明运行程序使用前腿 -0.6/1.0，后腿 0.6/-1.0。不是只从源代码推断。
- 错误同时进入观测 `q - q_default` 和目标 `q_default + action_scale * action`。不能指望相减和相加抵消：中间是非线性策略。
- export_onnx_fast.py 又把同一旧默认角写入元数据；C++ 没从该字段加载默认角。因此只改元数据也不能修复。
- 实际 staged ONNX 与原 PT 在30个原生观测上的最大动作误差为 9.54e-7。网络权重导出基本一致；部署语义仍不一致。shape/feature_contract PASS 未覆盖默认角。

## 确认二：修正零点不足以恢复正常平地姿态

同一 staged ONNX、同一 MuJoCo 机器人模型及 PD、同一起始姿态、同一固定前进指令，分别使用训练零点和部署零点。物理步长1ms，策略50Hz；静止2s、前进20s、再静止3s，统计5至21s，程序先确定该窗口。使用模型自带纯平面，不含楼梯、ROS、键盘、雷达噪声。

| 默认角 | 移动时平均机身高度 | 平均前向速度 | 重力横向分量范数 |
|---|---:|---:|---:|
| 训练匹配值 | 0.4798m | 0.6328m/s | 0.0231 |
| 部署现值 | 0.4565m | 0.6784m/s | 0.0612 |

部署现值下的12个腿关节平均角与用户日志选出的稳定异常姿态 RMS 差0.0317rad，复现了相同姿态模式。训练匹配值仍有四肢过度伸展，不能宣称对齐默认角即可解决。
停止指令后的机身高度分别恢复至0.5612m和0.5176m。问题与运动指令相关，纯平地、不经过楼梯也可出现，因此楼梯退出历史和雷达噪声不是出现该现象的必要条件。

## 确认三：上一轮防匍匐指标漏掉腿的几何姿态

`v111_support_cycle.flat_posture_cost` 只看机身净空、倾斜、晃动，无腿关节/轮相对髋位置/支撑跨度项。高度项只在净空低于0.40m时生效。
上表两组移动帧均未触发高度罚项；训练匹配组100%的统计帧同时未触发高度和倾斜罚项。此结论不包含角速度项，也不是宣称全部奖励为零。
FK 对用户日志稳定姿态的支撑平面重建估计净空0.4595m，拟合残差0.51mm，同样落在高度罚项死区。FK 是几何证据，不是动态回放或真实地面测量。

已有 hipy/knee nominal deviation 项权重均为-0.1，而前向速度奖励权重为5；不是完全没有腿姿态约束，但腿姿态约束较弱。转向/侧移时该关节项直接归零；高地面相对出生原点时还乘0.1。纯平地前进不需要这些门控缺口也能复现，所以它们不能冒充本例唯一根因。
停住时才有 stand_still_joint_deviation_l1（权重-1），正常行走时不生效。前进允许伸展、停止又恢复的行为与该奖励结构一致；需要通过修正后的闭环实验确认具体修法收益。

## 原生环境及边界

40-env 冻结原生回放确认真实默认角。原生随机指令与仅注入部署角偏差的诊断，纯平地移动样本平均净空分别0.5663m/0.5151m；轨迹分化后样本数440/390，不能按配对独立样本推断显著性，也不能拿随机方向均值代替固定前进表现。
固定前进的原生环境追加诊断见同目录 native_forward 文件，结论以追加摘要为准。
原生回放禁用了策略观测扰动以便定位；没有优化器更新。MuJoCo A/B 绕过ROS，不证明ROS全链路或上下楼过渡已经修复。原日志末尾超时位于异常姿态之后，不能解释此前已稳定重复的前伸。

## 修复顺序

1. 从该 checkpoint 的保存配置导出完整关节语义；部署按关节名加载默认角和动作尺度，缺失或与配置冲突则拒绝加载。观测、动作、默认保持及 standup 分开明确，不改机器人硬件校准偏置。
2. 在几何确认的平地中增加持续的全腿正常工作区约束，包含轮相对髋位置/腿前后伸展；高度与倾斜只作补充。楼梯真实支撑转移需保留自由度，不统一锁死关节。
3. 用固定向前、倒退、侧移、转向、停车再启动，以及上下楼出口分组复验；先修部署再评价同权重，之后才决定奖励修改和续训。不能靠“再训久一点”或仅提高高度项权重解释和解决本例。
