# V11：连续楼梯感知与显式安全落点奖励

## 1. 目标

在 V10 的第一阶感知基础上，V11 要让策略在整个楼梯通过过程中持续使用高程图，学习将轮子越过每一级立面的安全下界并保持横向 corridor 内；首个跨阶责任腿由策略自主决定，而不是由网络结构预先偏置给右前腿。

这里的“落点”必须区分两部分：

- **纵向 X 落点**：轮心越过第一道立面的安全下界；第二道立面不再定义后界；
- **横向 Y 落点**：轮心不靠近踏面侧边，位于可行走 corridor 内。

落点奖励是学习信号，不是硬控制器。策略仍输出 16D 动作，最终是否满足几何条件由 reward、MISS 事件、成功事件和评估判据共同约束。

### 1.1 2026-08-29 的 V11 前肢契约

V11 当前默认 `front_completion_mode="alternating_risers"`：首个立面允许 FL/FR 自主竞争，首先完成“净空 -> 越面 -> 支撑”的一侧只用于确定交替相位；下一道未结算立面只允许反侧累积信用，每次合法完成后再翻转。首个物理完成不发正奖，防止通过 reset 反复刷最容易的第一阶；正向 escrow 从第二个、且符合交替的物理完成开始结算。

目标净空高度始终相对当前期望腿应跨的真实上踏面计算，不增加固定抬腿高度。目标丢失或没有可确认的下一立面时 fail closed。前轮立面碰撞同时检查两个当前可见 slot，不受信用侧选择影响。

V12 显式覆盖为 `bilateral_same_riser`，保留同一立面的双前轮完成语义。V11/V12 Actor ABI 都仍为静态 `obs[1,63] -> actions[1,16]`。

## 2. V10 的已知边界

1. V10 的净空、碰撞和 FIRST 成功几何主要以右前轮 FR 为参考；`H/D` 也只具有到 FR 三个关节动作的直接网络通路。因此它不具备自主选择首个跨阶责任腿的能力。
2. V10 的 `B/H/D` 描述当前第一道有效立面。该 encounter 通过后会被 consume，只有连续一段无台阶后才 re-arm；因此连续楼梯中不会逐阶构建目标与给出逐阶几何奖励。
3. V10 没有轮心的显式 X/Y 落点区间或中心偏好；只要越过立面、在上踏面高度附近形成支撑，就可能满足 FIRST 判据。
4. V10 的越立面前净空判据不是固定“轮心抬高 10 cm”，而是动态相对高度：

   ```text
   wheel_center_z >= upper_tread_z + wheel_radius + clearance_margin
   ```

   当前轮子半径与 margin 的具体数值属于配置台账；该条件表达的是轮心相对当前上踏面的最低高度。V11 不应在缺少几何或动力学证据时随意提高该阈值。
5. V10 不存在显式的“右腿后必须抬左腿”状态机；当前问题是第一阶几何控制权被结构性偏置到 FR，而不是预先规定完整的左右腿顺序。

## 3. 连续立面感知表示

V11 在每个 control step 更新局部高程图，并从当前行进方向提取至少两道连续、可信的正立面：

```text
当前立面：B1, H1, D1
下一立面：B2, H2, D2
```

- `B1/B2`：对应立面是否已确认且可追踪；
- `H1/H2`：对应立面高度；
- `D1/D2`：从当前参考轮/机器人沿接近方向到对应立面的有符号距离；
- 第一踏面纵向深度：`T1 = D2 - D1`。

`B2` 必须保留。用 `H2=0` 或 `D2=0` 不能可靠区分“没有下一阶”“感知丢失”和“低矮障碍”。连续目标需要支持确认、滤波、有限帧 hold、失效和重新锁定；不能仅在第一次检测时冻结到 episode 结束。

若需要真正的 XY 落点，除上述纵向量外，还必须从高程图提供横向可行走 corridor 或踏面边界，例如：

```text
y_safe_min, y_safe_max
```

只有 `B1/H1/D1/B2/H2/D2` 时，V11 能构建纵向 X 落点约束，但还不能称为完整的 XY 落点约束。

## 4. 第一踏面安全落点区域

令 `x_riser1` 为第一道立面；在机器人当前接近方向坐标系中，轮心必须满足的纵向安全下界为：

```text
x_safe_min = x_riser1 + wheel_radius + margin_front
```

横向安全区间为：

```text
y_safe_min <= y_wheel <= y_safe_max
```

因此轮胎半径约束是安全区间的边界条件，不是唯一落点。reward 的优先级应为：

1. 越过第一立面安全下界且位于横向安全区：主要正奖励；
2. 接近横向中心：较弱 shaping reward；
3. 未越过第一立面下界或接近横向侧边缘：惩罚；
4. 形成上踏面稳定支撑：成功事件；
5. 始终保留实时 command-following：避免原地寻找落点。

不要使用“精确落到中心点”作为硬目标。不同速度、yaw、步态和载荷下，安全区间内的最优位置可能不同。

## 5. 缺失/无效感知的 fallback

| 感知和几何状态 | V11 行为 |
|---|---|
| 两道立面均可靠 | 启用连续立面感知、第一立面下界与横向中心 shaping |
| 仅第一道立面可靠 | 保留越立面净空、跨越、上踏面支撑；不把它误判为平台 |
| 横向安全区为空 | 不发落点正奖励，记录不可落点事件；不得静默当作成功 |
| 短时感知丢失 | 仅在规定 hold/hysteresis 窗口内保持目标；超时后撤销 |
| 零、后退或非接近命令 | 不启用向前跨阶落点 reward，保持实时 command 语义 |

横向安全区为空意味着可观测 corridor 不足以容纳轮子和侧向 margin；这必须是显式诊断项。

## 5.1 平台退出判别

Actor 的 `B1=B2=0` 不能单独表示“已上平台”，因为它也可能来自感知丢失。训练侧平台状态机要求同时满足：

1. 本次责任前轮已完成安全跨阶和上踏面支撑；
2. 原始高程图连续确认前方无有效正立面；
3. 两个后轮已越过本次锁定立面，且后轮接触稳定；
4. 条件首次成立时才发出一次 `platform_exit_success` 事件。

平台确认是隐藏的奖励／诊断状态，不改变 Actor 63D ABI。短时无立面帧、仅剩一个下一立面、或后轮尚未越界都不会触发成功。后续重新发现新的两立面目标时，旧 encounter 释放并恢复连续爬楼奖励。

## 6. 首跨责任腿由策略选择

V11 不再将 `H/D` 直接绑定到 FR 专用 head。策略应从前轮候选（至少 FL/FR）中自主形成首跨动作；若要扩展到四轮，需要分别定义后轮在跨阶过程中的职责。

reward 不能简单对所有轮子相加，否则可能诱导多腿同时抬起。需要定义一次 encounter 的“责任轮”机制：

```text
候选前轮形成动作
    -> 最先满足有效净空、越立面和上踏面支撑条件的轮成为责任轮
    -> 在本次 encounter 中锁定
    -> 直到通过、失败、目标失效或 reset 才释放
```

所有与 V10 FR 绑定的项目都必须泛化到责任轮：净空进度、立面碰撞/MISS、FIRST 成功、teacher labels、动作幅度和日志指标。训练与评估应加入左右镜像或对称性检查，避免模型退化为新的固定偏置腿。

## 7. Actor / Critic / 部署 ABI

最小连续两立面输入使 Actor 从：

```text
57D official proprio + B1/H1/D1 = 60D
```

变为：

```text
57D official proprio + B1/H1/D1 + B2/H2/D2 = 63D
```

若加入横向安全带或踏面中心信息，Actor 维度会进一步增加。V11 必须冻结并逐字段验证新 ABI，包括：

- Actor 网络结构和输入顺序；
- Critic 的特权地图/真值输入；
- Runner 的维度 gate 与 observation manifest；
- ONNX 导出、推理端输入顺序和部署端高程图提取；
- 旧 60D checkpoint 不兼容的处理方式。

高程图中的 simulator-only 真值可以用于 Critic 与 reward，但 Actor 的每一维输入必须能由真机传感器在线得到。

## 8. 实施与验收

V11 的修改应分开验证，不能将净空高度阈值、连续目标、落点 reward 和责任腿选择混为一次不可归因的大改。

### 必测项目

1. 两立面提取：不同台阶高度、踏面深度、yaw 偏差、噪声和感知短时丢失下的有效率与误检率。
2. 几何：X/Y 安全区间计算、空区间、第一/第二立面碰撞、上踏面支撑。
3. 训练：V10 基线、仅连续感知、连续感知加落点 reward、完整责任轮选择四组对照；固定 seed、地形和 command 分布。
4. 任务指标：FIRST/MISS/FULL 成功率、第二立面碰撞率、轮心 X/Y 落点误差、边缘越界率、沿 command 的速度和倒退比例。
5. 命令边界：零命令、后退、侧移和转向时不应因感知而主动向楼梯靠近。
6. 对称性：FL/FR 首跨选择比例、对应成功率和镜像场景一致性。
7. 部署：高程图时间同步、输入延迟、点云缺失/误检、ONNX 输入 ABI 与真机控制频率。

所有“通过”结论必须来自 V11 当前配置下的真实运行，不得用 V10 的静态几何验收或旧 checkpoint reward audit 替代。
